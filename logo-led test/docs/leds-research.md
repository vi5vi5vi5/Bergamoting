# Подсветка Мини 3: как устроено и как с ней работать

Снято с живой колонки 26.10.2026 (прошивка `.117`, `bergamot`).

## Железо

### Кольцо: 6 RGB-зон через `/dev/fb0`

| Что | Значение |
|---|---|
| Устройство | `/dev/fb0`, имя `logo`, 6×1 пикселей, 24 bpp |
| Кадр | 18 байт со смещения 0, **порядок байт BGR**, зона 0 — первые 3 байта |
| Запись | синхронная, ~1,5 мс на кадр (`WriteAt(frame, 0)`) |
| Общая яркость | `/sys/class/graphics/fb0/device/backlight/*/brightness` (0–255, сейчас 255) |
| Зеркало в sysfs | `bergamot:{red,green,blue}:logo0..5` с триггером `ledfb-logo` — только отражают fb0, писать туда не надо |
| Калибровка цвета | `ledconfigs/<цвет корпуса>.json` — матрица 3×3; цвет корпуса `yandex-getcolor` → `gray` (файла нет, значит без коррекции) |

Проверено глазами: 6 зон различимы по отдельности.

### Часы: 4 цифры по 7 сегментов

`/sys/class/leds/bergamot:white:clock<сегмент><позиция>/brightness`, 0–255.

- Позиции `0..3` — цифры слева направо.
- Сегменты `A..G` — стандартная семисегментная разметка (A верх, B правый верх,
  C правый низ, D низ, E левый низ, F левый верх, G середина).
- `DH` + `DL` — двоеточие, `DM` — средняя точка, `DEGREE` — значок градуса.
- Прошивка рисует яркостью ~14 в тёмной комнате (подстраивает по датчику освещённости).
- Таблица цифр → сегменты лежит в `quasar.cfg`, секция `leds.clock.frameBuilder`.

## Как подсветкой пользуется прошивка

`quasar_launcher2` запускает один бинарник `maind` в четырёх ролях: `--platformd`
(основной: Алиса, звук, светодиоды, сеть — всё потоками внутри), `--mediad`,
`--telemetry`, `--fluent-bitd`.

### Шина между сервисами

Каждый сервис слушает свой порт на `127.0.0.1` (protobuf-сообщения по TCP) —
даже если живёт в том же процессе. Порты из `quasar.cfg`:

| Порт | Сервис | Порт | Сервис |
|---|---|---|---|
| 9875 | aliced | 9906 | audioclient |
| 9877 | wifid | 9908 | update_health_check / calld |
| 9878 | authd | 9910 | iohub_clients |
| 9882 | config_capability | 9911 | ntpd |
| 9884 | firstrund | 9912 | setupd |
| 9887 | metricad | 9913 | ble_initd |
| 9891 | external_commandsd | 9917 | networkd |
| 9895 | monitord | 9921 | stereo_pair |
| 9898 | brickd | 9922 | volume_manager |
| 9899 | glagold (наружу 1961) | 9924 | backend |
| 9900 | mediad | 9926 | network_stats |
| 9903 | iohub_services | 11124 | multiroomd |

Отдельного «LED-сервиса» с портом нет — подсветка живёт внутри `platformd`.

### Конвейер подсветки внутри `platformd`

```
состояние Алисы (SDK) ─┐
спектр музыки ─────────┼─> device_state_handler ──> пара анимаций [кольцо] [часы]
громкость, BT, звонки ─┘                              │            │
директивы из облака ──> LedCapability ────────────────┘            │
                                                      ▼            ▼
                                     LedFrameBuffer (mmap /dev/fb0)  ClockLedController (sysfs)
```

В логе (`/data/quasar/daemons_logs/maind.log`) каждое переключение видно так:

```
Play animations: [ .../oknix//alice_listening.led ] [ .../clock/alice_listening.binscled.zst ] source=onSDKState
Play animations: [ idle.led ] [ spectrogram ] source=onSDKState
```

- Анимации кольца — `ledpatterns/oknix/*.led`, текстовые:
  ```
  gammacorrection            # необязательно
  loop                       # необязательно: зациклить
  e800f3 e800f3 e800f3 e800f3 e800f3 e800f3 240   # 6 цветов RRGGBB (зоны 0..5) и длительность кадра, мс
  ```
- Анимации часов — `ledpatterns/clock/*.binscled.zst` (бинарные, сжаты zstd; формат ещё не разобран).
- `spectrogram` — визуализация музыки на часах, 15 с после старта трека.
- `led_util <файл.led>` проигрывает любую анимацию кольца отдельно от Алисы.
- Путь `/dev/fb0` зашит в `maind`; путь к сегментам часов задаётся в `quasar.cfg`
  (`leds.clock.brightnessFilename`).

### Кто кого перетирает (проверено)

- **Кольцо.** В покое прошивка в fb0 не пишет — наш кадр держится. Но на **любое**
  изменение состояния SDK (не только «Алиса слушает», но и смену трека) она
  проигрывает `idle.led` = всё чёрное и стирает наш кадр.
- **Часы.** Прошивка перерисовывает время на каждой смене минуты (наш «12:34»
  продержался 39 с), плюс во время анимаций и спектрограммы.

Вывод: свой LED-сервис должен следить за fb0/сегментами и заново занимать их,
когда прошивка закончила свою анимацию.

## Замеры: Go на колонке и SSH с Windows

| Что | Результат |
|---|---|
| Сборка | `GOOS=linux GOARCH=arm64 CGO_ENABLED=0`, бинарник 1,7 МБ, запускается без доработок |
| Анимация на колонке, цель 60 fps | интервал кадров p50 16,667 мс, p99 16,684 мс, max 16,704 мс |
| Память Go-процесса | RSS 1,9 МБ |
| Подключение SSH с Windows | ~110 мс |
| Команда через новую SSH-сессию | p50 23 мс, p95 35 мс, max 44 мс |
| Команда в уже открытую оболочку | p50 6,7 мс, p95 14 мс |
| Пинг до колонки | 2–5 мс |

На колонке нет `scp` и `sftp-server`: файлы заливаются через
`ssh ... 'cat > /путь'` (или из Go — через stdin SSH-сессии).

Эксперименты: [`experiments/ringspin`](../experiments/ringspin/main.go),
[`experiments/sshbench`](../experiments/sshbench/main.go).

## Рекомендуемая архитектура

Агент на колонке + клиент на Windows, один Go-модуль на обе части.

```
Windows                                         Колонка
┌──────────────────────┐   SSH :2222   ┌──────────────────────────────┐
│ клиент (Go)          │──────────────>│ dropbear                     │
│ • ввод IP и порта SSH │  деплой, старт, │                              │
│ • заливка/обновление │  логи         │ ledd (Go, ~2–5 МБ RAM)        │
│   агента             │               │ • движок анимаций 60 fps     │
│ • UI                 │── API ───────>│ • слои: прошивка > уведомл.  │
└──────────────────────┘ (тоннель SSH  │   > наша сцена               │
                          до 127.0.0.1)│ • следит за fb0 и часами,    │
                                       │   уступает Алисе и возвращает│
                                       │   своё после                 │
                                       │ • /dev/fb0, clock* sysfs     │
                                       └──────────────────────────────┘
```

Почему так:
- Анимации считаются на колонке — ровно и без лагов Wi-Fi; работают при выключенном ПК.
- Только агент может быстро заметить, что прошивка стёрла кадр, и вернуть его.
- SSH остаётся единственной «дверью»: клиент через него ставит агента и ходит в
  его API тоннелем (`ssh.Client.Dial` в Go), новый порт в сеть не открывается.
- Общие типы API в одном пакете для обеих программ; обе собираются одной командой.

Вариант «только Windows по SSH» годится для разовых команд («залить красным»),
но не для анимаций (23–44 мс на команду, рывки) и не умеет отвоёвывать кольцо
у прошивки.
